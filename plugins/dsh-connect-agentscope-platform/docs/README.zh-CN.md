## 做什么

AgentScope Platform 用 Credits 结算模型调用，它的控制台本来就能看余额——这个插件把那个账户搬进 DSH，不用再开浏览器标签页，并且可以选择让模型调用走这个平台。

- **模型供应商，可选。** 默认关闭。在设置页打开后，模型选择器里才会出现 `AgentScope Platform`；关掉立即撤下，不需要重启。额度、签到与用量在开关关闭时照常工作。
- **模型目录自己说了算。** 从平台获取可用模型、手动添加，并逐行编辑：模型 ID、显示名称、上下文窗口、输出上限、输入类型（默认文本与图片都勾选），以及推理档位和每档发送的 API 参数值。
- **输入框下方的额度读数。** 模型选择器旁边一小条，显示可用 Credits 与可兑换贡献值，五分钟自动刷新，也能手动刷新。它不会挡住输入；只在当前会话用 AgentScope 的模型时才出现，换到别家供应商就自动收起。这条读数和设置页里同一个账号的额度、以及「最近刷新」时间来自**同一次测量**——输入框刷新一次，账号行就跟着更新，两处不会各说各的。
- **账号池。** 多个 AgentScope 平台账号可以并存，由你决定新请求走哪一个。每个账号自带一套登录 token、模型密钥、额度历史与签到记录；在页面上添加、重命名、禁用、删除，或者交给插件按额度与阈值自动挑。
- **设置页。** 账号池、两套各司其职的凭证（登录 token 用于账户查询，`sk-as-` 密钥用于模型调用）、供应商开关、目录编辑、每日签到、额度余额、可领取的赠送、贡献值兑换、按日期范围/记录类型/模型筛选且可翻页的用量明细，以及控制台的**价目表**——按能力分组，默认全部收起，展开才看明细。

## 安装

```sh
dsh plugin --profile web add @summerscar/dsh-connect-agentscope-platform
```

重启 DSH，然后打开 **设置 → AgentScope Platform**。

> **桌面端：** 从桌面应用的插件页安装。`desktop` profile 由 Electron 应用独占管理，`dsh plugin --profile desktop` 会被 DSH 本身拒绝。

## 配置

1. **账号池。** 页面上是一份账号列表，每个账号各有自己的凭证、额度与签到记录，一眼能看出哪个是计费账号、凭据还能不能用、最近一次报出多少额度。
   - **管理列表。** 粘贴 refreshToken 即可添加账号，之后随时重命名、禁用、重新启用或删除。禁用只是把它从自动选号里摘出去，记录不会丢。
   - **选定计费账号。** 有且只有一个账号是**计费账号**：所有没指定账号的请求都记在它头上；切换之后，从那一刻起新发起的请求才用新账号。
   - **按额度自动选号。** 打开后设一个阈值：计费账号额度低于阈值时，插件在下一轮检查里比较其他可用账号，换到额度最高的那个。关掉就完全手动。
   - **给单个账号测活。** 测活只针对一个账号，并把结论标出来——凭据失效、额度不足，还是健康——坏掉的账号因此不会被选中，而不是悄悄失败。网络抖动不会被记成凭据失效。
   - **单独改一个账号的凭据。** 每行都能展开它自己的编辑区：换 refreshToken、获取或粘贴模型密钥、设置这个账号的拉取间隔。这些字段永远属于你展开的那一行。供应商开关、模型目录与模型元数据由所有账号共用。
2. **登录凭证。** 只填 **refreshToken** 就够了：保存时插件会立刻拿它换出一对可用的 token，之后自己续期。refreshToken 每用一次都会轮换，一次换取会签发新的一对、旧的随即作废。获取方式：在已登录 platform.agentscope.io 的浏览器控制台执行 `localStorage.getItem('refreshToken')`，把结果粘进去。也可以改填 `accessToken`，但它约两小时就过期。
3. **模型密钥。** 点「用登录态获取」（平台只在生成或重置后返回完整密钥），或手动粘贴一个 `sk-as-…`。「重置并重新获取」会轮换密钥，旧密钥立即失效。
4. **模型供应商。** 想让 AgentScope 出现在模型选择器里时，再打开它。这是整台机器共用的一项设置，不按账号各存一份。
5. **模型目录。** 点「获取可用模型」，勾选要的，再逐行修改。上下文窗口与输出上限**故意留空**——这个插件不编造数字：空着的输入框里用灰字显示公开模型表的取值范围（最小值~最大值），你填了就以你为准，清空即恢复该表的值。目录由所有账号共用。
6. **每日签到。** 打开后，插件每天保活一次登录态，并回查平台的贡献值明细，报告今天到底有没有计入。

## 主要限制

- **平台没有签到接口。** 它的「每日登录 +1」是服务端在登录时自动计分，所以这个插件的做法是保活登录、再回查明细。页面只会报告「已计入 / 待平台计分 / 失败」三种状态，绝不会仅凭自己发过请求就宣称签到成功。
- **只接了对话这一种能力。** 对话端点接受文本与图片输入，所以模型行默认是「文本 + 图片」。图片**生成**、语音合成、语音识别与视频走另一套协议，不在本插件范围内。
- **推理档位要逐模型开启。** 平台没有统一的参数名，所以只有你在某一行启用并填了参数值，该档位才会写进请求。
- **模型容量是插件自己的占位值，或来自第三方公开表**，不是平台公布的数字。每一行都能改，目录里也会显示数字来自哪里。
- **模型供应商依赖宿主自带的 pi-ai 适配器。** 宿主没带这个包时，开关打开也不会注册出路由；额度、签到与用量照常工作。
- **切换账号只影响新发起的请求。** 已经在输出的会话会用它开始时那个账号跑完，切换从你下一次发起的请求才开始生效。
- **不做请求内的自动故障切换。** 一次请求失败就是失败——不管是两次检查之间额度突然耗尽，还是自上次测活之后凭据过期。插件不会拿它去换账号重试；你要么手动切号，要么等下一轮自动选号挑一个更健康的账号。打开自动选号并不等于请求不会失败。

凭证只留在服务端。浏览器拿到的永远是掩码，页面里不会写入任何 token。
